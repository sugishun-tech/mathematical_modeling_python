Example 7.1: Group testing of diodes

Source: textbook PDF pp. 226–231.

Problem statement

Each diode is independently defective with probability 0.003. Testing one diode costs 5 cents. Testing a series group of costs cents; if the group fails, all diodes are tested individually at 5 cents each. Choose an integer group size minimizing expected testing cost per diode. Explain why the single-diode case must not use the group-retesting formula.

The decision assumes independent failures and perfect tests. Those are model assumptions, not facts established by the computation.

Approach and verification

Expected cost is a weighted average over a passing group and a failing group. Treat a group of one separately to avoid charging for a redundant retest. Search integer sizes and use a lower bound to rule out the unsearched tail.

Python · cell 4 · execution 2
p = 0.003

n = np.arange(1, 61)

cost = np.where(n == 1, 5.0, 4 / n + 6 - 5 * (1 - p) ** n)

best = int(n[cost.argmin()])

value = float(cost.min())

assert best == 17 and value < 5

assert 6 - 5 * (1 - p) ** 61 > value

print('Optimal integer group size:', best, '; cost per diode (cents):', value)
Optimal integer group size: 17 ; cost per diode (cents): 1.484264961220581
Python · cell 5 · execution 3
plt.plot(n, cost, marker='.', markersize=3)

plt.scatter([best], [value])

plt.xlabel('group size (diodes)')

plt.ylabel('expected cost (cents/diode)')

plt.title('Group testing: account for failed groups and the n=1 exception')

plt.show()

Interpretation and limits

The cheapest group size is 17 under the stated assumptions. A smooth continuous optimum would only suggest where to check neighboring integers. Defect dependence, imperfect tests and batching overhead would all change the cost model.

Example 7.2: Expected payoff from two dice

Source: textbook PDF pp. 227–230.

Problem statement

Roll two independent fair six-sided dice. The payoff equals their sum. Derive the full distribution, compute its expectation and variance, and compare the running mean in repeated simulations with the theoretical expectation. Does one finite sample path prove the strong law of large numbers?

Approach and verification

List the 36 equally likely ordered outcomes, then aggregate by their sum. Calculate both the mean and variance from the exact distribution. Compare those with a cumulative mean from independent simulated games.

Python · cell 9 · execution 4
from itertools import product

outcomes = np.array([sum(pair) for pair in product(range(1, 7), repeat=2)])

assert np.isclose(outcomes.mean(), 7) and np.isclose(outcomes.var(), 35 / 6)

values, counts = np.unique(outcomes, return_counts=True)

display(pd.DataFrame({'sum': values, 'probability': counts / 36}))

Example 7.3: Correcting a counter for dead time

Source: textbook PDF pp. 231–234.

Problem statement

Radioactive events arrive as a Poisson process at unknown rate events/second. A type-I (nonparalyzable) counter is locked for seconds after each counted event. Events during that fixed lock period are missed and do not extend it. Given observed inter-count intervals spanning seconds, derive a corrected estimate of and its sensitivity to .

Memorylessness gives each observed interval with . Hence and

The denominator must be positive. Near the maximum observable count rate , small timing errors are strongly amplified.

Approach and verification

For a nonparalyzable counter, each registered event consumes a fixed dead time plus an exponential waiting time until the next registrable event. Use this renewal-cycle mean to solve for the original event rate. Keep count rate and underlying event rate distinct.

Example 7.4: Are 153 monthly emergency calls unusually few?

Source: textbook PDF pp. 234–239.

Problem statement

A community averages 171 emergency calls per month. Assume independent exponential interarrival times with mean month, equivalently a Poisson count with mean 171 in a fixed month. A month has only 153 calls. Assess whether that count is ordinary variation using the book's two-standard-deviation arrival-time approximation and an exact Poisson calculation.

For arrivals, the approximate arrival-time range is . Invert this condition by asking whether the fixed month length 1 is inside that range. The author's correction changes the upper integer endpoint to 199, not 198. A two-standard-deviation approximation is not an exact 95% interval.

Approach and verification

For the textbook approximation, invert the interval for the sum of exponential interarrival times. Separately calculate an exact Poisson interval for the count in a fixed month. These are related but not identical constructions.

Python · cell 18 · execution 7
from scipy.stats import poisson

mean = 171

n = np.arange(1, 400)

accepted = n[(n - 2 * np.sqrt(n) <= mean) & (mean <= n + 2 * np.sqrt(n))]

assert accepted.min() == 147 and accepted.max() == 199

print('Inverted two-standard-deviation arrival-time range:', accepted.min(), accepted.max())

print('Exact central 95% Poisson interval:', poisson.ppf([0.025, 0.975], mean))

print('P(N<=153) under the stated model:', poisson.cdf(153, mean))

assert 153 in accepted

Example 7.5: Advection and diffusion of an airborne plume

Source: textbook PDF pp. 239–243.

Problem statement

A pollutant is released 10 km upwind of a town. Wind is a constant 3 km/hour. At one hour the plume width is 2 km and its peak is 20 times a specified reference level. Interpret “width” as four standard deviations, giving km/hour under the convention .

Find the maximum concentration at town, the time of that maximum, and the two crossings of the reference level. Derive and verify the Gaussian point-source solution; distinguish a unit-mass probability density from concentration. Treat the reference level as part of this historical exercise, not current exposure guidance.

A Gaussian has infinite support; the “2 km cloud” describes a central portion, not a hard boundary.

Approach and verification

Translate cloud width into a standard deviation using the stated four-standard-deviation convention. The Gaussian kernel integrates to one; a mass scale turns it into concentration. Verify the PDE algebraically, then solve separately for the peak and the two threshold crossings.

Python · cell 23 · execution 9
from scipy.optimize import brentq, minimize_scalar

x = sp.symbols('x', real=True)

t, D = sp.symbols('t D', positive=True)

u = sp.exp(-x * x / (2 * D * t)) / sp.sqrt(2 * sp.pi * D * t)

assert sp.simplify(sp.diff(u, t) - D / 2 * sp.diff(u, x, 2)) == 0

print('Symbolic check: the Gaussian kernel solves Ct=(D/2)Cxx.')

concentration = lambda time: 20 / np.sqrt(time) * np.exp(-(10 - 3 * np.asarray(time)) ** 2 / (0.5 * np.asarray(time)))

peak = minimize_scalar(lambda time: -concentration(time), bounds=(0.01, 10), method='bounded')

assert peak.success

left = brentq(lambda time: concentration(time) - 1, 0.01, peak.x)

right = brentq(lambda time: concentration(time) - 1, peak.x, 10)

exact_peak = (-0.5 + np.sqrt(0.25 + 16 * 9 * 100)) / (4 * 9)

assert np.isclose(peak.x, exact_peak, atol=1e-05)

assert abs(concentration(left) - 1) < 1e-08 and abs(concentration(right) - 1) < 1e-08

print('Peak time (h), peak/reference:', peak.x, concentration(peak.x), 'crossings:', left, right)

times = np.linspace(0.2, 7, 700)
